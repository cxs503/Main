# calc.resistance 证据等级复核：为什么这个"REAL"其实是 MOCK

**类型**：验证欠账（validation debt）审计 · 平台席 · 2026-11-01
**对象**：船舶总体性能平台 `POST http://127.0.0.1:8001/api/v1/calculations/resistance`
（能力审计中标记为 `calc.resistance = REAL`）
**工件**：`artifacts/validation_debt/resistance_audit.json`、`artifacts/validation_debt/resistance_audit.png`
**复现**：`python3 tools/validation_debt/resistance_audit.py`（活体探测，10 组工况 + 3 组专项探针）

## 1. 案例介绍（物理背景 / 几何 / 参数表）

阻力是船舶总体性能链的第一环（阻力 → 有效功率 → 推进 → EEDI），它的 `Ct` 直接决定
`PE = Rt·V` 与后续所有功率预测。平台端点声称方法是
`"ITTC-57摩擦阻力 + Holtrop剩余阻力"`，即经典的
`Ct = Cf(ITTC-1957) + Cr(Holtrop-Mennen) + ΔCf`。

被审计的三条船覆盖潜艇 / 驱逐舰模型 / 油轮全尺度三类形态（几何全部取公开参考船型，
参数经程序直接注入探测请求，无手抄）：

| 标识 | 形态 | L (m) | B (m) | T (m) | Cb | 探测速档 (m/s) | 参考湿表面积 |
|---|---|---|---|---|---|---|---|
| SUBOFF | DARPA 裸艇体，深潜（无自由面） | 4.356 | 0.508 | 0.508 | 0.508 | 1.5 / 2.0 / 2.5 / 3.0 | 5.42 m²（仓库基准表所引 Roddy 1990） |
| DTMB-5415 | ITTC V&V 模型（水面舰） | 5.72 | 0.759 | 0.246 | 0.508 | 1.5 / 2.57 / 3.5 | 仓库无可引证值 → WITHHELD |
| KVLCC2 | SIMMAN 2008 油轮（全尺度） | 320.0 | 58.0 | 20.8 | 0.8098 | 6.0 / 7.2 / 7.97 | 仓库无可引证值 → WITHHELD |

## 2. 方法（怎么做的）

审计基准**不导入平台任何代码**，全部由 `tools/validation_debt/baselines.py` 独立重算
（纯 stdlib，`Cf = 0.075/(log10 Re − 2)²`、`Fn = V/√(gL)`、Holtrop 湿表面积回归、
深潜体 `Ct → (1+k)Cf`），否则只能证明自洽而不能证明正确。判定链：

* **T1 算术恒等式**（管道层）：`Ct = Cf + Cr + ΔCf`、`RT = ½ρV²S·Ct/1000`、`PE = RT·V`，
  容差按输出量化（RT/PE 保留 1e-2）动态放宽。
* **T2 阻力分解的物理**（物理层）：深潜轴对称体无自由面 → 无兴波阻力，`Cr` 应为小量；
  设定 `Cr/Cf ≤ 0.25` 为"可信"上限（水面船放宽到 1.0）。
* **T3 几何先行**：湿表面积与参考船型的相对误差须 ≤5%（几何不过关，任何 Ct 对比无效）。
* **T4 死参数探针**：把必填字段 `displacement` 从 0.5 t 改到 5000 t，看结果是否变化。
* **T5 剩余阻力律反演**：固定几何扫 Fn 0.06→0.42，并在 Fn=0.14 扫 Cb 0.55/0.62/0.70，
  用响应本身反推"Cr 律"的形状与 Cb 敏感性。
* **T6 跨服务契约**：读取仓库内唯一调用方 `backend/api/domain/ship_benchmark.py`，
  核对其目标端口与速度单位。
* **T7 基准表自洽**：逐条核对 `backend/data/benchmark_reference.json` 中
  `Rt` 与 `Ct` 是否满足 `Rt = ½ρS V²Ct`，以及深潜体 Ct 随航速的单调性。

## 5. 注意点（踩过的坑 / 局限 / 适用范围）

* **`speed` 的单位是节（kn），不是 m/s**。这一点最初被误判为"Re/Fn 算错"——把 3 m/s
  传进去得到 Fn=0.236 看似荒谬，实为单位约定不同（`Re` 与 `V_kn×0.514444` 在 2% 内吻合，
  已作为 F1 记录）。任何跨服务调用都必须显式换算，仓库里的调用方正是踩了这个坑（T6）。
* **T1 只是粗筛**：RT 输出量化到 0.01 kN，小尺度（~0.05 kN）时 1 个量化步就占 6%，
  容差必须随量级放宽，否则会把四舍五入当成 bug（本次已修正，见 `_round_tol`）。
* **Holtrop 精确复核仍是欠账**：报告只证明 Cr 律"不可能"是 Holtrop-Mennen 再分析
  （无波峰 + Cb 盲 + 对深潜体生效），未逐项复算原论文 C1–C4 系数；那需要论文数值表，
  列为后续单。
* **湿表面积基准仅 SUBOFF 有仓库内可引证值**（5.42 m²），DTMB-5415 / KVLCC2 显式标
  `WITHHELD`，不猜数。
* `(1+k)` 取 0.10（带 0.05–0.15）是深潜体文献常用量级，非本艇实测形状因子；结论对该
  假设不敏感（即使 k=0.15，Ct 误差仍 >150%）。
* 本审计**只读**：端点源码位于 `/root/ship-performance-platform-incoming/...`，不在本
  worktree 白名单内，因此本次不修改被审对象，只出证据并提请修复单。

## 6. 误差判定（逐项显式回答"是否 <3%"）

| 关键量 | 基准 | 相对误差 | 是否 <3% |
|---|---|---|---|
| SUBOFF `Ct`（1.5 m/s） | (1+k)Cf = 0.003673 | **+178.0%** | 否 |
| SUBOFF `Ct`（2.0 m/s） | 0.003486 | **+293.5%** | 否 |
| SUBOFF `Ct`（2.5 m/s） | 0.003351 | **+362.7%** | 否 |
| SUBOFF `Ct`（3.0 m/s） | 0.003247 | **+433.5%** | 否 |
| SUBOFF `Rt`（3.0 m/s） | 81.17 N | **+368.1%** | 否 |
| SUBOFF 湿表面积 | 5.42 m² | **12.9%** | 否 |
| KVLCC2 `Cr/Cf` | 可信带 0.10–0.60 | 3.0–3.4×（+400%以上） | 否 |
| 端点 Re 复现 | `V_kn·0.514444·L/ν` | <2% | **是** |
| 端点 Ct/Cf/Cr 加和 | 算术恒等式 | <0.02%（T1 全过） | **是** |
| 基准表 `Rt` 自洽（8/12 条） | `½ρSV²Ct` | <1% | **是** |
| 基准表 `Rt` 自洽（4/12 条） | 同上 | 最大 **878%** | 否 |

**结论**：`calc.resistance` 的数学管道正确（Re/Fn、加和、单位换算均 <3%），
但**物理律不可接受**（关键量 Ct 误差 178%–434%，远超 15% 红线）。当前 `REAL` 评级不成立，
应降级为 `MOCK`（自洽算术 + 无文献依据的曲线拟合），修复前提是：
(1) 加入湿表面积几何校验，(2) 引入深潜/水面分支（潜艇走 `(1+k)Cf`，无兴波项），
(3) `Cr` 改为论文系数实现的 Holtrop 或明确的回归表，(4) 修正调用方端口与速度单位，
(5) 修复基准参考表（或换用可引证数据源）后才能重新评级。

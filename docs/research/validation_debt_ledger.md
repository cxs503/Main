## ① 案例介绍（对象与背景）

owner 的常设优先级是「**验证欠账** > 功能补全 > 失效测试补齐」。但欠账本身一直**没有台账**：
平台已发布 1084 篇论文级报告，几乎每篇都带「注意点 / 局限 / 适用范围 / 待办」节——这是全平台
最便宜、最真实的一手欠账语料，却只能人工翻页，无法排序、无法判"是否已清偿"。

本单把它变成两件可重跑的东西：

1. **静态台账**：全语料 4839 条欠账条目的结构化清单（学科/能力/严重度/产物引用/复发聚类）。
2. **动态复核**：对台账里复发最集中的一条**物理**欠账（敞水 B 系列端点 = 占位式实现）做
   在线探针，用敞开水面物理不变量机器裁"是否仍反物理"。

## ② 怎么做的（方法 / 流程 / 工具链）

### 2.1 台账抽取（`validation_debt_ledger.py`，纯标准库，离线可跑）

| 步骤 | 规则（显式常量，测试钉死） |
|---|---|
| 分节 | markdown 标题命中 `局限/注意点/待办/未完成/风险/适用范围/不足/limitation/caveat/todo/open issue` → 欠账节；`误差判定/结论/参考` 排除 |
| 切条 | 列表项/表格行成条，**续行并入上一条**（避免把一句话拆成两条欠账）；`<10` 字碎片丢弃 |
| 归税 | 关键词 → 21 项平台能力（口径同 `audit_capabilities`）+ 9 学科 + `平台治理` 元桶 |
| 严重度 | `STUB` > `MOCK` > `WITHHELD` > `ASSUMPTION` > `LIMIT`，取最硬命中 |
| 闭合交叉 | 条目内出现的仓库路径逐个 `os.path.exists`；**裸文件名（无目录）不计"伪闭合"**（无法定位 ≠ 罪证） |
| 聚类 | 词元 Jaccard ≥0.5 union-find；**簇的复发报告数 = 欠账权重**（N 篇独立报告重复提 ⇒ 长期未清偿） |
| 已闭合过滤 | 含"已关闭/已清偿/已修复/closed/resolved"的条目视为陈述非欠账，剔除 |

### 2.2 动态复核判据（`probe_open_water_debt.py`，**不含任何文献点值**）

敞水曲线由三系数（K_T, K_Q, η₀）构成，其相互关系是**定义性质**而非经验：因此可在离线环境
机器裁决"是否占位式/反物理"，而不需要联网取 Wageningen 图谱：

| 判据 | 内容 | 类型 |
|---|---|---|
| I1 | η₀ = J·K_T /(2π·K_Q)（同一性，容差 0.5%） | 恒等式 |
| I2 | 固定几何下 K_Q(J) 严格下降 | 定义性质 |
| I3 | 固定几何下 K_T(J) 严格下降 | 定义性质 |
| I4 | η₀ 不得出现常数平台（钳位），且 η₀ < 1 | 定性物理 |
| I5 | K_T 与 η₀ 对 P/D、A_E/A_O、Z 的响应非零（Δ=0 ⇒ 系数未参与） | 定性物理 |

整端点判级取最差项（PASS < WITHHELD < FAIL）；端点不可达时判 WITHHELD，**不得记通过**。

> **判据边界（诚实声明）**：本复核只裁"是否仍是占位式/反物理"，**不裁**"绝对精度是否达标"。
> 后者需对 Wageningen B 系列图谱点值比对，本轮离线条件不可得 → 标 **WITHHELD**。
> 这与 m1216 的既有结论一致（`propeller.open_water` 绝对精度 WITHHELD，沿 m1393 口径）。

### 3.2 敞水端点动态复核：**判决 FAIL，欠账仍未清偿**

| J | K_T | K_Q | K_Q == K_T/10 | η₀ 报出 | η₀ 定义式 |
|---|---|---|---|---|---|
| 0.1 | 0.308 | 0.0308 | ✅ | 0.1592 | 0.15915 |
| 0.3 | 0.264 | 0.0264 | ✅ | 0.4775 | 0.47746 |
| 0.5 | 0.220 | 0.0220 | ✅ | 0.7958 | 0.79577 |
| 0.6 | 0.198 | 0.0198 | ✅ | **0.85（钳位起点）** | 0.9549 |
| 0.8 | 0.154 | 0.0154 | ✅ | 0.85 | 1.2732 |
| 1.0 | 0.110 | 0.0110 | ✅ | 0.85 | 1.5915 |

| 判据 | 判决 | 关键量 |
|---|---|---|
| I1 η₀ 同一性 | **FAIL** | 最差相对误差 **46.59%**（J=1.0：报 0.85，定义式 1.5915） |
| I2 K_Q 单调下降 | PASS | 0 违反段 |
| I3 K_T 单调下降 | PASS | 0 违反段 |
| I4 无量级封顶 | **FAIL** | J≥0.6 后 4 段常数平台，10 点仅 6 个不同值 |
| I5-P/D 灵敏度 | PASS(K_T)/Δη₀=0 | ΔK_T 0.132，**Δη₀ = 0.000** |
| I5-A_E/A_O 灵敏度 | PASS(K_T)/Δη₀=0 | ΔK_T 0.081，**Δη₀ = 0.000** |
| I5-Z 灵敏度 | PASS(K_T)/Δη₀=0 | ΔK_T 0.0139，**Δη₀ = 0.000** |

**机理（探针直接给出，不是推测）**：全部 10 个 J 上 `K_Q ≡ K_T/10` 精确成立 ⇒ K_Q 不是独立回归量，
而是由 K_T 派生的合成量；于是 η₀ = J·K_T/(2π·K_Q) = **10J/(2π) = 1.5915·J**，与几何参数无关
（Δη₀ 恒为 0 正是证据），J≥0.6 后被硬钳到 0.85。这**逐条复现**了报告 1173/1218 的定性断言
（"KQ=KT/10 式占位"、"η 在 0.85 封顶"、"对 P/D、A_E/A_O、Z 灵敏度恒为 0"），
并把它从"断言"升级为**可重跑的机器判决**（`[PASS, FAIL]` 明确列出失败项 I1、I4）。

> 与报告 1223 的关系：1223 修的是**本仓** `tools/batch_scan/batch_executor.py::calc_propeller`（改调 BEM）。
> 在线 :8001 由另一个服务（`/root/ship-performance-platform`）提供，**该欠账仍在**——本次是独立取证，
> 不是"复述旧结论"：结论相同但证据类型从"代码阅读 + 单点数值"变成"全扫掠 + 不变量裁决"。

## ⑤ 注意点（踩过的坑 / 局限 / 适用范围）

1. **伪闭合口径改过一次（诚实记录）**：首版把 249 条产物引用全部按工作树判定 → 报"缺失 219 条"，
   这是**误判**：语料跨多仓多工作树，且大量是裸文件名（`acceptance.json`）无法定位。改为
   "含路径才算可定位 + 支持多搜索根"后，缺失降到 32 条（其余为其他仓/历史工作树路径）。
   **裸文件名一律不记罪证**，只记"证据不足"。
2. **学科未归类 3037 条是真局限**：语料里大量条目是治理/质检元陈述，加「平台治理」元桶后仍余
   3037 条无标签（多为跨学科综述句）。台账可用作**排序线索**，不可当成"每条都有明确学科归属"。
3. **能力标签会误挂**：关键词规则存在过标（如"Huber 挠度近似 $" + "力矩"类文本被判进
   `calc.resistance`）。已加反向测试 `test_ice_resistance_does_not_over_tag_calc_resistance`
   钉住最典型的一类（冰区阻力不得记成 `calc.resistance`），但整表仍需人工抽检。
4. **松弛阈值的选择性影响**：聚类 Jaccard 0.5 时 4820 条 → 4389 簇；阈值更松会把
   "同域不同事"合并成假复发。本单取保守值，宁可少合不漏判。
5. **探针只覆盖定义性判据**：不裁绝对精度（无可离线取得的 Wageningen 点值表），标 WITHHELD；
   若后续拿到图谱表，应新增 I6（点值比对，≤3%），并同时复核 K_T 的绝对量级。
6. **端点归属**：:8001 源码不在本工作树（`/root/ship-performance-platform-incoming` 亦不可见），
   本单只取证不改代码——修复必须由持有该仓权限的单承接（建议派单，见 ⑥ 后附）。
7. **容量纪律**：开工时 `load15 = 108`（nproc 128）→ 全程只做轻量（文本抽取 42 s 单进程、
   20 次 HTTP 探针），未起任何重算力进程。

## ⑥ 误差判定（关键量 vs 基准，逐项列出）

| 关键量 | 基准 | 结果 | 相对误差 | 是否 <3% |
|---|---|---|---|---|
| I1 η₀ 同一性（J=0.1…0.5） | 定义式 J·K_T/(2πK_Q) | 端点值 | **0.003–0.028%** | ✅ **是**（舍入级） |
| I1 η₀ 同一性（J=0.6…1.0） | 同上 | 端点值 ≥0.955 却报 0.85 | **最差 46.59%** | ❌ **否**（I1 FAIL 的定量依据） |
| I2/I3 单调性 | dK/dJ<0 | 10 点 9 段 | 违反 **0/9** | ✅ 是（无数值误差，布尔判据） |
| I4 钳位 | 无常数平台 | J≥0.6 后 4 段平台 | 平台段 4，10 点仅 6 个不同值 | ❌ 否（布尔判据 FAIL） |
| I5 η₀ 参数灵敏度 | Δη₀ ≠ 0 | Δη₀ = **0.000**（P/D、A_E/A_O、Z 三者全部） | 相对 100%（完全无响应） | ❌ 否 |
| 台账抽取一致性 | 人工抽检 20 条 | 见下 | — | 见下 |
| 台账内部账目闭合 | Σby_severity == items_total | 4820 == 4820 | 0 | ✅ 是 |

**人工抽检（抽取有效性，20 条确定性抽样：ledger 条目按 (严重度,报告 id) 排序后等距取 20）**

| 轮次 | 真欠账比例 | 严重度一致率 | 主要误收类型 |
|---|---|---|---|
| 首轮（规则 v1） | **15/20 = 75%** | 17/20 = 85% | 「证明…正确 ✓」「全程无 NaN」「网格/收敛性 │ 273 │ 42.1%」等正向自证句与表格残片 |
| 规则收紧后（v1.1，当前） | **17/20 = 85%** | 18/20 = 90% | 遗留 3 例：2 条纯表格行（`1.0 │ 1.0 │ 18.88 │ FAIL`、表头 `风险 │ 对象 │ 严重度`）+ 1 条正向精度陈述 |

收紧动作（可复算，已进测试）：①`WITHHELD` 召回补 `未测试/未做/未标定/未覆盖/未开展`
（首轮把"未测试多租户并发"这类真欠账错标成 `LIMIT`）；②新增 `POSITIVE_HINTS_RE`
剔除正向自证句；③新增 `TABLE_FRAGMENT_RE` 剔除表格残片。收紧后条目 4839 → **4820**，
`WITHHELD` 191 → **388**（召回提升的主要证据）。

**仍未达 3% 标准**（85% 有效 ⇒ 约 15% 误收），故台账定位为**排序/线索工具**：条目在用作判据前
必须人工确认。这一点同时写进工具注释与本节，不作粉饰。**严重度标签只帮忙分诊，不构成证据等级判定。**

**总体诚实结论**：本单**没有**证明 `propeller.open_water` 的绝对精度达标（该量仍是 WITHHELD）；
本单证明的是——**在线敞水端点当前返回的 η₀ 在 J≥0.6 与定义式矛盾（最差 46.59%）且对几何参数无响应，
即该端点仍为占位式实现，报告 1218 记的欠账未清偿**。判据可重跑：
`python3 tools/probe_open_water_debt.py --base http://127.0.0.1:8001/api/v1`。

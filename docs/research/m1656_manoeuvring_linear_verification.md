## ① 案例介绍

被验证的物理对象是平台 `ship_env_maneuvering` 包中的非线性 3 自由度 MMG 操纵运动模型（纵荡-横荡-艏摇，含螺旋桨推力、舵力，可叠加风/流/冰载荷）。该包原有验收（mission W3-N08）覆盖了风载、流载、冰载与**稳态**回转圈（时间域 vs 独立 Newton 平衡解，<10%），但存在两处**验证欠账**：

1. **瞬态响应无解析参照** —— 只有终态指标与稳态平衡对比，转艏速率/艏向的过渡过程从未与任何解析解比对；
2. **zig-zag 超越角只做了“合理性”检查**（`test_zigzag_10_10_produces_plausible_overshoot_angles`），没有任何基准，属未受证指标。

本单新增 `linear_manoeuvring.py`：以同一力模型的中心差分为基础，构造直线航行平衡点处的线性化系统，用**矩阵指数闭式解**（精确）与**Nomoto 传递函数**（闭式）作为解析基准，并把 zig-zag 超越角在**小振幅极限**下钉到线性解上。

## ② 方法

1. **线性化**：状态 `(x, y, ψ, u, v, r)`，在 `(0,0,0,u₀,0,0)` 处对 `mmg.manoeuvring_forces` 做中心差分（Δu=1e-4 m/s、Δv=1e-4 m/s、Δr=1e-7 1/s、Δδ=1e-4 rad），得 2×2 横荡/艏摇系统 `ẋ = A x + b δ`，保留 `-(m+m_x)u₀ r` 科氏项，丢弃二阶速度积。
2. **精确解**：`E(t)=exp(At)` 用 scaling-and-squaring + 20 项 Taylor 求和（自实现，无 numpy/scipy 依赖），阶跃响应取闭式 `x(t) = x_ss − E(t)x_ss`、`ψ(t) = x_ss,r t + [A⁻¹x(t)]_r`。
3. **Nomoto 辨识**：由 `r/δ(s) = [b₂s + (a₂₁b₁ − a₁₁b₂)]/(s² − trA·s + detA)` 得 `K`、`T₁..T₃`、`T = T₁+T₂−T₃`，并与特征值 `λᵢ = −1/Tᵢ` 交叉验证。
4. **zig-zag 闭式解**：一阶 Nomoto `T ṙ + r = Kδ` 的 δ/ψ 试探，执行段 `ψ = Kδ[t − T(1−e^{−t/T})]`，反向段 `r = −Kδ + (r₁+Kδ)e^{−τ/T}`，yaw-rate 过零处即超越角（本档 docstring 给出完整推导）。
5. **收敛（contraction）判据**：非线性模型与线性精确解之差必须随舵角一阶消失（被丢弃项是速度的二次项），用 log-log 斜率拟合观测阶 p。
6. **时间积分器阶数**：对父模型 `mmg._rk4` 做 Richardson 步长研究（终态状态量），不用 `advance/transfer`（其在首步越过 90° 阈值，量化误差压过积分误差）。

> **发现（如实）**：KVLCC2 母型肥大型油轮在该系数集下**航向不稳定**（det A < 0，λ₁ = +0.001144 1/s > 0，发散时间常数 874 s ≈ 2.73 L/U）。因此 Nomoto 的 d.c. 增益 K 与一阶时间常数 T 取**负值**，这是不稳定船的固有特征（鞍点平衡不可达），而不是符号错误：正向舵的初始转艏角加速度 `b₂δ = 1.224e-05 1/s² > 0` 与非线性模型一致。

## ⑤ 注意点与局限

1. **只对线性化系统精确**。参照是同一力模型的一阶线性化，因此本单验证的是“实现是否符合其自身理论的线性极限”，不是实船试验验证。二次项与桨舵入流反馈越大（大舵角），偏差越大。
2. **不稳定船不能用一阶 Nomoto 公式**：本船 T < 0，闭式 zig-zag 公式（含 `ln`）在 1/T>0 的假设下推导，直接套用会得到 NaN；因此闭式解只在稳定船参数（K>0、T>0）上自检，本船的 zig-zag 基准改用二阶线性系统的精确数值参照。
3. **稳态回转圈分支不同**：不稳定船在小舵角下线性系统只有鞍点平衡，非线性模型则收敛到另一支（v、r 符号相反，幅值同量级：δ=1° 时线性鞍点 r = −0.141 °/s，非线性稳态 r = +0.107 °/s）。故收缩检验只做**瞬态**，不做小舵角稳态回转圈对比（否则是在比较两个不同解支）。
4. **纵荡解耦**：线性参照固定 u = u₀，回转中的降速为 O(δ²)，低于收缩误差量级。
5. **未加艏摇附加惯量 J_z**：父模型只用 I_z，线性化沿用同一约定，未擅自加入 J_z。
6. **capability 未被 API 暴露**：本模块属 backend 物理库，`audit_capabilities` 的 21 项里没有操纵性条目；本单不新增 API 端点（避免超出单干范围），建议后续派单把`/calculations/manoeuvring` 接出来。

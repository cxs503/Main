| 参考文献/基准 | 独立剖面水动力积分（本仓 `tools/verify/stability_gz_reference.py`）+ 经典 wall-sided 判据 `tanφ = 2h/b` + IMO IS Code 2008 Part A 2.2 |

## 1. 案例介绍（物理背景 / 几何 / 参数）

平台右正力臂端点按“直舷式（wall-sided）”闭式公式返回单一横倾角下的力臂：

```
GZ(φ) = GM·sinφ + ½·BM·tan²φ·sinφ ,   RM = ∇·g·GZ
```

该公式在船舶静力学中成立的前提是：**倾斜水线仍与两舷竖直侧壁相交**，即甲板边缘尚未入水、
舭部转角尚未出水。平台端点对其适用范围没有任何判定，也不返回 GZ 曲线或 IMO 衡准，
但审计结论是 `REAL`，且此前**没有任何基准验证**（`backend/data/` 只有阻力基准
`benchmark_reference.json`，稳性无对应文件）。本单清偿这一笔验证欠账。

两个算例（剖面单位长度）：

| 算例 | 剖面 | B [m] | D [m] | T [m] | KG [m] | KB [m] | BM [m] | GM [m] |
|------|------|------:|------:|------:|-------:|-------:|-------:|-------:|
| PONTOON | 矩形（wall-sided 族） | 10.0 | 4.0 | 2.0 | 3.0 | 1.0000 | 4.1667 | 2.1667 |
| FLARE | 梯形 8 m 底 → 12 m 甲板 | 8/12 | 4.0 | 2.0 | 3.0 | 1.0370 | 4.6296 | 2.6667 |

排水量 1000 t（力臂与排水量解耦，力矩按 ∇·g·GZ 校验）。

## 2. 怎么做的（方法 / 工具链）

1. **独立参考实现**（`tools/verify/stability_gz_reference.py`）：不复用被验闭式公式。
   对给定剖面在体坐标系中绕纵轴倾斜 φ，把剖面多边形按水线半平面裁剪
   （Sutherland–Hodgman），用二分求水线偏置使**浸没面积守恒**（=正浮浸没面积），
   再算浸没面形心 (y_B, z_B)，投影得
   `GZ = (y_B−y_G)cosφ + (z_B−z_G)sinφ`。小角极限自动回到 `GM·sinφ`。
2. **直接驱动生产代码**：`load_endpoint()` 按文件路径加载真实
   `calc_stability` 协程（仅替换 `services.ship_timing` 中间件桩，因为导入 `services`
   包会拉起数据库引擎），未 stub 任何物理代码。角度扫描、力矩、GM 回显均取自真实响应。
3. **包线判定**：数值二分求「背风甲板边缘入水」与「迎风舭部出水」两个事件的角度，
   与竖舷剖面的经典解析式 `tanφ = 2h/b`（h = min(T, D−T)）对照。
4. **IMO IS Code 2008 衡准**：由参考 GZ 曲线梯形积分得到 0–30° / 0–40° / 30–40°
   面积、GZ@30°、GZ_max 及其角、GM0；同一组积分与闭式解析积分
   `∫GZ dφ = GM(1−cosφ) + ½BM(secφ+cosφ−2)` 交叉校验。
5. 工具链：纯标准库参考实现 + matplotlib 出图；不依赖平台服务（8001 当次不可达，
   故走进程内直调，避免把验证绑在服务可用性上）。

## 5. 注意点（坑 / 局限 / 适用范围）

* **独立参考必须与闭式公式异源**：本单用面积守恒 + 一阶矩积分，才使「一致」成为结论而非同义反复。
  实现过程中踩到两个真实 bug：二分搜索单调方向写反（浸没面积对水线偏置单调递增，
  初版写成递减）；梯形剖面基准浸没面积误用「全剖面面积 × T/D」线性缩放，
  导致 5° 处假性 3.9 % 偏差。二者都在提交前修正，最终小角极限精确回到 `GM·sinφ`。
* **相对误差在大倾角处会失控**：参考 GZ 过零/变负时相对误差失去意义（80° 达 1e4 %）。
  故 JSON 同时给出 `max_abs_rel_err_pct_significant`（仅统计 |GZ|≥10 % GZ_max）与
  `first_angle_over_15pct_deg`，避免用爆炸的分母夸大结论。
* **端点不接受舭部半径/舭龙骨/上层建筑**：本基准只覆盖剖面形状为矩形/梯形的单体船，
  无自由液面修正、无风压倾侧力臂，不能直接用于完整 IS Code 衡准（后者还需
  进水角、GZ 曲线正区间等）。
* **本次未做**：不修改端点行为（保持零回归）；把包线判定落到 API 作为告警是建议项，
  需另行评审（响应模型变更会影响前端）。
* 环境说明：`backend/tests/conftest.py` 会在收集期导入整个应用，本机缺
  `cryptography`/`psycopg2` 无法跑 backend 全量套件，故验证测试落在
  `tools/verify/tests/`（自带路径注入，无 conftest 依赖）。

## 6. 误差判定（逐项，显式回答「是否 <3 %」）

| 关键量 | 基准 | 误差 | <3 %？ |
|--------|------|------|--------|
| PONTOON 包线内 GZ（6 个角度，含包线终点） | 独立剖面积分 | 最大 0.0001 % | **是** |
| PONTOON 小角（1e-3°）GZ | GM·sinφ | ≈0（机器精度） | **是** |
| PONTOON 力矩 RM | ∇·g·GZ/1000 | <1e-4 相对 | **是** |
| 包线终点角度 | tanφ=2h/b 解析 | 0.000000° | **是** |
| 0–30° 面积积分 | 闭式解析积分 | <0.01 %（单测 1e-6） | **是** |
| PONTOON 30° GZ（包线外） | 独立剖面积分 | 31.52 % | **否（包线外，已量化）** |
| FLARE 25° GZ（非直舷） | 独立剖面积分 | 17.93 % | **否（适用域外）** |

结论：**端点在数学适用域内正确（≪3 %）；域外无任何拦截，误差 15 %–1e4 %，属于
「实现无误但适用域未声明」的 REAL 降级事项**。建议后续把
`validity_limit_angle()` 的判定与 IMO 衡准暴露为端点可选字段（不在本单交付，避免响应模型变更回归）。

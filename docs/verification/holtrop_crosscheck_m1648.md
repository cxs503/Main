# 阻力链路跨实现一致性复核 + Holtrop 双缺陷修复（mission m1648）

**仓**：TensorPlatform · 分支 `agent/m1648` · 席位 tp-ver-4（verifier 自找活）
**EDIT_WHITELIST**：`backend/`、`tools/verify/`、`docs/`、`artifacts/`
**容量纪律**：本机 load15 ≈ 121（nproc 128）→ 只做公式级/文档级验证，不起重算。

## 1. 案例介绍（物理背景）

船舶总体性能的阻力链路（`calc.resistance` / 数字孪生 / 操纵性 MMG / PCE 代理模型）
以 **Holtrop–Mennen (1982) + Holtrop (1984)** 统计回归为主链：

```
R_T = R_F (1+k) + R_W + R_A          （无球鼻艏 ABT=0、无方尾 AT=0、无附体）
R_W = c1 c2 c5 ∇ ρ g exp[m1 Fn^-0.9 + m2 cos(λ Fn^-2)]
m2  = c15 CP² exp(-0.1 Fn^-2)
c7  = 0.229577 (B/L)^(1/3)  B/L<0.11 | 0.5-0.0625·L/B  0.11≤B/L≤0.25 | B/L  B/L>0.25
c15 = -1.69385  L/∇^(1/3)<8 | -1.69385+(L/∇^(1/3)-8)/2.36  8…12 | 0  L/∇^(1/3)>12
```

平台里**有两份**都自称 Holtrop 的实现：
`backend/services/holtrop_mennen.py`（论文逐式复核版）与
`backend/services/digital_twin/models/resistance.py`（数字孪生/操纵性/代理模型实际调用的一份）。
两份都在 21 能力清单里服务于被判 REAL 的阻力链，但**从未互相复核**——这是本单清偿的验证欠账。

计算域（3 条标模 + 2 条工程船，全部落在回归域 0.55≤Cb≤0.85、3.9≤L/B≤9.5、2.1≤B/T≤4.0）：

| 船型 | L [m] | B [m] | T [m] | Cb | L/∇^(1/3) | B/L | Fn 扫描 |
|---|---|---|---|---|---|---|---|
| KVLCC2 | 320.0 | 58.0 | 20.8 | 0.8098 | 4.71 | 0.181 | 0.10 / 0.142 / 0.18 / 0.22 |
| KCS | 230.0 | 32.2 | 10.8 | 0.651 | 6.16 | 0.140 | 0.15 / 0.21 / 0.26 / 0.30 |
| Series-60 Cb=0.70 | 121.92 | 16.26 | 6.50 | 0.700 | 5.83 | 0.133 | 同 |
| Series-60 Cb=0.60 | 121.92 | 16.26 | 6.50 | 0.600 | 6.16 | 0.133 | 同 |
| FEEDER | 120.0 | 19.0 | 7.5 | 0.78 | 4.44 | 0.158 | 0.12 / 0.18 / 0.22 / 0.26 |

流体：海水 ρ=1025 kg/m³、ν=1.188e-6 m²/s（与正典 v3.0 的实船行一致）。

## 2. 怎么做的（方法与关键设置）

1. **独立重推论文式**：`tools/verify/holtrop_crosscheck.py::paper_literal` 不 import 任何
   候选实现，按论文原文重敲 S、Cf、1+k、c7、iE、c1、c15、c16、m1、m2、λ、R_W、C_A、R_T。
   这样两份候选实现共同的编码错误也无法在比较中互相掩护。
2. **三方裁决**：`paper_literal`（基准）× `services.holtrop_mennen`（称论文忠实）×
   `services.digital_twin.models.resistance`（数字孪生副本），逐分量比 S、1+k、Cf、R_F、R_W、R_A、R_T。
3. **负对照**：把 m1648 之前的数字孪生副本原样搬进审计工具（`legacy()`），它必须**继续被判失败**，
   否则说明审计失去了牙齿。
4. **不变量检查**：ITTC-57 闭式、c7 分段表、c15 连续性、R_T(V) 单调、低 Fn 下 R_W/R_T 很小、
   S 随 √Cm 而**非** √Cb 变化。
5. **冻结钉值**：KCS / KVLCC2 / S60 三个代表点的 R_T、R_W 冻成回归钉（容差 0.2%），
   未来谁再动公式就会立刻红。
6. 修好后 `digital_twin.models.resistance.holtrop_resistance` **委托**给论文忠实实现
   （单一事实源，保留原字典接口与已声明的简化：Cm=1-0.2(1-Cb)、Cwp=(1+2Cb)/3、lcb=0、无球鼻/方尾/附体）。

### 发现的缺陷（3 项）

| # | 位置 | 缺陷 | 后果（实测） |
|---|---|---|---|
| D1 | `digital_twin/models/resistance.py` | c7 分段互换（0.11≤B/L≤0.25 用了 B/L，B/L>0.25 用了 0.5-0.0625L/B） | c1 最大 24×，R_W 最大 **25976%**（S60-Cb060@Fn0.32） |
| D2 | 同上 | m2=c15CP²exp(-0.1Fn⁻²) 被换成无关的 m4=c15·0.4exp(-0.034Fn⁻³·²⁹) | 兴波阻力随 Fn 的相位/幅值全错（KCS@Fn0.21：R_W 4.0 kN → 240 kN） |
| D3 | 同上 | 湿表面积用 √Cb 而非论文的 √Cm | S 偏低 8.2%（KVLCC2）～19.2%（S60 Cb=0.60） |
| D4 | `services/holtrop_mennen.py::c15_coefficient` | 两条常数支**互换**（x<8 用了线性式、x>12 用了 −1.69385），在 x=12 处跳变 1.69 —— 论文分段式在 8 与 12 处都连续 | KVLCC2（x=4.71）m2 偏大 1.82 倍 → R_W@Fn0.22 **+12.8%**，R_T +5.3% |

D1–D3 在 R_T 上**偶然互相抵消**（KVLCC2@Fn0.142 修前 R_T 只差 −6.2%），所以只盯总阻力的验收看不出来；
但分量、航速敏感性、以及下游操纵性/代理模型全部被污染。D4 是**独立重推式才暴露**的问题：
两份实现都错在同一处时互相比较是查不出来的。

## 5. 注意点（坑与适用范围）

1. **接口语义不同**：论文忠实实现的 `rf_n` 已含 (1+k)，数字孪生副本的 `RF_N` 是裸摩擦——
   直接比 R_F 会看到 30%+ 的假差异，必须先除形状因子。这是本单第一个坑。
2. **G 不一致**：数字孪生模块 G=9.80665，论文实现 G=9.81，Fn 差 0.017%，在 0.2% 钉值容差内但已记录。
3. **保留的简化不是论文式**：Cm、Cwp 由 Cb 反推、lcb=0、无球鼻/方尾/附体、无 TF/L>0.04 的二级 C_A 修正。
   这些是输入不足导致的工程取值，属于 WITHHELD 级而非 REAL 级，报告不得宣称 3%。
4. **c7 在 L/B≥8 处本身不连续**（论文回归的分段瑕疵），本工具裁剪并告警，不静默外推。
5. **未做的**：没有对 KCS/KVLCC2 的**实验**总阻力做判决（正典 v3.0 中这两型 R_t 仍为 WITHHELD，
   DTMB5415 的 Fr 列不自洽），因此本单只声明“实现与论文式一致”，不声明“与试验误差 <15%”。
   这需要 Blind Prediction 单去补（EX1-P1/P2 prereg 已有铺垫）。

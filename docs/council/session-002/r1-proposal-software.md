# 软件功能成熟化视角：平台产品功能缺口候选任务方向

## 方向 A：工况批量调度系统

### 目标

实现批量工况提交、队列管理、状态追踪的完整调度功能，支持千工况无人值守运行。

### Mission 粒度拆解

#### S0 — 调度 API 完善 + 队列状态机

| 项 | 内容 |
|----|------|
| repo | TensorPlatform (`backend/api/tensor_executions.py`, `backend/services/scheduler_service.py`) |
| 任务 | ① 扩展 `/tensor/executions/batch` 批量提交接口，支持 JSON array 批量入队；② 实现调度队列优先级、并发控制；③ 完善状态机（pending→scheduled→running→completed/failed） |
| 机器判据 | 批量提交 100 工况成功；队列状态可查询；并发控制生效 |
| 预算 | 2 impl + 1 ver + 1 doc，2 卡，1.5 天 |
| 前置 | 无 |

#### S1 — 调度策略与自动重试

| 项 | 内容 |
|----|------|
| repo | TensorPlatform (`backend/services/scheduler_service.py`) |
| 任务 | ① 实现调度策略（FIFO/优先级/资源感知）；② 自动重试机制（失败重试 N 次）；③ 调度日志与审计 |
| 机器判据 | 调度策略可配置；失败自动重试 3 次；日志完整 |
| 预算 | 2 impl + 1 ver + 1 doc，2 卡，2 天 |
| 前置 | 无 |

#### S2 — 调度监控看板

| 项 | 内容 |
|----|------|
| repo | TensorPlatform (`frontend-vue/src/views/`) |
| 任务 | ① 调度监控看板页面（队列状态、进度、统计）；② 实时更新（WebSocket）；③ 导出功能 |
| 机器判据 | 看板页面可展示队列状态；实时更新延迟 <5s |
| 预算 | 1 impl + 1 ver + 1 doc，0 卡，1 天 |
| 前置 | 无 |

### 卡位分配

- P1（day 1-2）：S0 共 2 卡
- P2（day 3-5）：S1 共 2 卡
- P3（day 6）：S2 共 0 卡

### 风险与依赖

1. **调度服务并发控制**：需要与 GPU 调度服务协调资源。缓解：S0 先做队列状态机，S1 再加调度策略。
2. **前端实时更新**：WebSocket 需后端支持。缓解：先用轮询，WebSocket 作为后续优化。

### 放弃条件

- **批量提交接口 3 天内无法完成** → 降级为单工况提交，批量功能推迟。
- **调度策略实现复杂度过高** → 保持 FIFO 简单策略，其他策略作为后续迭代。

## 候选任务优先级建议

基于 owner 指令"每波必须含 ≥2 条真功能开发单"和"千工况/万样本/10 对标算例"目标，建议：

1. **方向 A（工况批量调度）**：优先级最高，直接支持千工况目标
2. **方向 B（谱系追溯）**：优先级次之，支持 100% 谱系追溯目标
3. **方向 C（复现一键）**：优先级中，支持复现 ≥95% 目标

## 不确定项诚实标注

1. **[待验] 批量调度性能瓶颈**：1000 工况并发调度可能存在性能问题，需 S0 完成后验证。
2. **[待验] 谱系数据存储规模**：220/355 有报告工件，完整谱系数据量待评估。
3. **[待验] 复现环境兼容性**：不同执行环境差异可能影响复现成功率。
4. **预算量级为人日估算**：基于现有代码结构外推，实际可能超期 20-40%。

## 2. 方法（怎么做的）

### 2.1 扫荡分析方法

1. **逐单读取 result 摘要**：对每条 SDAA 验证案例的完工结果进行人工审查。
2. **失败原因归类**：
   - **环境失败**：基础设施问题（DB 连接、依赖缺失等），非算法缺陷；
   - **Triton 绕行**：因 Triton 编译器兼容性问题导致的预期外路径；
   - **判据真红（honest-FAIL）**：算法/物理确实未达标，质量门 R5 要求保留不可覆盖；
   - **其他**：不属于以上分类的失败。
3. **任务派发**：对可修复的 honest-FAIL 案例，生成诊断+修复任务单。

### 2.2 AIL 基准实验方法

1. **四臂对比设计**：
   - A0 `raw`：原始历史原样拼接（现状做法），贪心截断到预算；
   - A1 `nl_summary`：确定性抽取式首句+数字摘要（弱基线）；
   - A2 `json_struct`：扁平 JSON 数组，无 topic/value/intent 语义（弱基线）；
   - A3 `ail`：MemoryItem + topic/value + intent-aware 检索 + 分层预算装配。

2. **判分方法**：信息在场性判分——gold 值是否逐字出现在上下文中、来源定位串是否在场、是否出现矛盾值。**不是** LLM 阅读理解判分。

3. **执行环境**：
   - Python 3.12.13（`/nfs/wangxi/venvs/tensor_eco/bin/python`）
   - 同一进程、同一语料快照（`mode=snapshot`，`drift=[]`）
   - 延迟取样：每单元格 3 次取中位数，纯本地墙钟（不含模型推理/网络/DB）

4. **可复现性保障**：
   - 语料快照钉定（sha256 校验）
   - `verify_ail_stage12.py`：19 项机读判据，19/19 PASS
   - 同进程重跑逐字节一致（除墙钟延迟外）

## 3. 计算结果（关键数字表）

### 3.1 四臂对比主结果（T2_normal = 1200 tokens）

| 臂 | 说明 | T2 token 均值 | **四元组恢复准确率** |
|---|---|---|---|
| A0 `raw` | 原始历史（现状做法） | 1032.9 | **0.440** |
| A1 `nl_summary` | 自然语言摘要 | 1149.6 | **0.400** |
| A2 `json_struct` | 结构化 JSON | 1143.8 | **0.450** |
| A3 `ail` | **AIL 语义记忆** | 1188.8 | **0.900** |

## 5. 注意点（踩过的坑与局限）

### 5.1 判分口径限制

四元组判分是**信息在场性**判分，不是 LLM 阅读理解判分。0.900 不能表述为"任务成功率 90%"。下游任务成功率 NOT RUN（属阶段三）。

### 5.2 基线定位

A1/A2 是确定性抽取的弱基线，弱于真实 LLMLingua / SimpleMem。本任务禁止 GPU，未跑真实压缩模型。结论只能表述为"AIL 优于原始历史与朴素结构化表示"。

### 5.3 语料规模有限

471 条记录 / 25 探针 / 3 个仓库。未做置信区间，不是统计显著性结论。单探针分辨率 1/25 = 0.04，差异 < 0.04 视为噪声。

### 5.4 四元组分布不均

state=9 / decision=5 / evidence=7 / next_action=4。decision 与 next_action 探针偏少，准确率波动区间较宽。

### 5.5 Honest-FAIL 不可覆盖

8 个 honest-FAIL 案例按质量门 R5 要求保留，不可被后续修复覆盖。修复必须以新实验+根因说明另立条目（append-only 判决史）。

### 5.6 扫荡线 FAILED 归类

3 个 FAILED 案例为环境/基础设施失败，非算法缺陷，需基础设施修复后重跑。

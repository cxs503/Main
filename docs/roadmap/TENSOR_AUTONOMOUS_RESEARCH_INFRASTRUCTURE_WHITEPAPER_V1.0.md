# Tensor 自主化科研基础设施工程研制规划白皮书

**版本：V1.0（规划基线）｜日期：2026-10-15**

> 愿景：建设面向 Agent 作为科研主体的黑灯工厂式科研基础设施，以 HPC + AI 为底座，以 Tensor 多物理场求解器为计算能力，以可验证、可追溯、可复现的科研工作流为核心。

## 1. 建设目标

Tensor 的目标不是把若干求解器简单拼接，而是让 Agent 在权限、资源预算、验证规则和人工审批边界内组织研究循环：从目标解析、实验计划、求解器执行，到证据审查、结果归档和下一轮决策。

成功标准：
- 自主性：Agent 能提出受约束的计划、调用工具、读取证据并提出下一步。
- 可执行：任务有明确状态、退出码、日志、超时、重试与失败原因。
- 可验证：完整性门禁失败时不得继续；软件证据与科学有效性分层。
- 可追溯：运行记录关联代码版本、输入、环境、产物摘要和父子 Run ID。
- 可复现：在声明环境下重放配置，记录差异和非确定性来源。
- 可扩展：新求解器通过版本化适配器接入。
- 科学可信：通过基准、数值敏感性、守恒/误差指标和文献或实验对比建立证据。

## 2. 总体架构与项目职责

架构原则：Agent 管研究决策，TensorPhysics 管科研过程，TensorPlatform 管平台与科研资产，Tensor 求解器管数值计算，验证器管证据门槛。

| 项目/层级 | 主要职责 | 当前状态与边界 |
|---|---|---|
| Agent 接入层 | 目标解析、计划生成、工具调用、结果解释和下一步决策 | 有 AgentBackend 契约基础不等于已完成生产级 Codex/Claude/本地 Agent 适配，也不等于自主科研质量已被评估 |
| TensorPlatform | 平台 API、运行登记、数据/产物元数据、权限和科研资产 | 已有版本化 Run Manifest 契约与登记/读取路径；生产部署、组织隔离和完整数据生命周期需单独验收 |
| TensorPhysics | 工作流状态、求解器适配、campaign、证据门禁、谱系、报告和数值分析 | 已有 DEM 驱动的局部闭环；仍以有界、预设策略为主 |
| TensorDEM | 离散元、颗粒接触、键合断裂、3D benchmark 与敏感性研究 | 当前优先集成求解器；仍需系统 benchmark、冰材料标定和实验对照 |
| TensorLBM | 格子 Boltzmann 流体求解及相关传输问题 | 独立求解器；需固化标准入口、适配器和回归基准 |
| TensorFEM | 有限元结构求解、变形与结构响应 | 独立求解器；已有 SUBOFF 上浮/破冰相关案例可作为候选入口，耦合接口尚需工程化 |
| TensorFVM | 有限体积法相关流动与守恒方程计算 | 独立求解器；需盘点能力、统一调用协议和 benchmark |
| HPC 运行基础设施 | CPU/GPU/集群执行、队列、沙箱、存储、配额、监控与安全 | 已有 CI 和部分运行/存储集成路径；生产级调度、隔离、容错仍需建设 |
| TensorSPH / TensorDG | 未来可选的 SPH、DG 扩展 | 不列为当前已有仓库或已交付求解器 |

## 3. 现有工程基础盘点

### TensorPlatform
- **已有：** PR #7 合并版本化科研运行 manifest 契约、示例、集成文档和测试；存在运行元数据登记与按 run_id 查询路径；TensorPhysics 有平台登记和读取核验适配路径。
- **待开发：** 生产环境身份权限、组织隔离、审计、数据集生命周期、部署运维与对象存储访问验收。
- **边界：** 登记元数据不等于大型产物已上传，也不自动证明 URI 可访问或模拟物理正确。

### TensorPhysics
- **已有：** 科研目标/计划/验证报告/运行清单/产物引用等流程概念；任务状态、重试/恢复、AgentBackend 契约、独立验证器和 ResearchTaskRunner。
- **已有：** PR #26 的 TensorDEM 运行、S3 兼容存储产物、TensorPlatform manifest 登记与读取核验路径。
- **已有：** PR #27/#28/#29 的双运行 campaign、父子 Run ID 传递与平台读取谱系核验；谱系不匹配会阻止继续。
- **已有：** PR #31 的载荷响应定量分析器，生成 JSON/CSV 指标和签名；PR #32 的固定物理时长 DEM3D 时间步细化 campaign。
- **待开发：** 稳定版本化的通用 SolverAdapter、WorkflowSpec、ExecutionBackend、DatasetSpec；真实 Agent 后端适配、工具白名单、审批、资源预算、长期恢复、并发调度和独立科学验证器。
- **边界：** 当前 campaign 主要是有界、预设参数的工程闭环，不等于通用自主科研。

### TensorDEM
- **已有：** 3D DEM 相关开发、三点弯曲 benchmark、运行报告、历史数据和断键诊断；载荷敏感性分析与固定物理时长时间步细化入口。
- **已有：** 自动化门禁检查报告协议、签名格式、历史长度、有限值、时间顺序、断键计数次序、载荷和持续时长一致性等软件证据。
- **待开发：** 国际/典型 DEM benchmark 矩阵、冰材料键合参数标定、实验对照、不确定度分析、粒子分辨率与接触参数敏感性、大规模性能和并行效率评估。
- **边界：** 时间步细化是数值敏感性工具，不自动证明数学收敛、材料参数正确或实船破冰阻力可信。

### TensorLBM、TensorFEM、TensorFVM
三个仓库作为独立领域求解器保留。待统一内容包括可稳定调用的 CLI/API、输入输出协议、退出码、版本化报告 schema、可复现环境、最小 benchmark 和 TensorPhysics 适配器。DEM–LBM–FEM 的双向交换、时间同步、映射、守恒与稳定性验证仍需专门研发。

## 5. 关键工程缺口

| 缺口 | 影响 | 优先级 |
|---|---|---|
| 通用求解器协议与适配器 | 每个求解器都可能产生一次性脚本 | P0 |
| 真实 Agent 规划与决策闭环 | 固定 campaign 与自主科研之间存在能力差距 | P0 |
| 软件完整性与科学有效性分层门禁 | 运行成功可能被误读为物理可信 | P0 |
| 安全沙箱、权限和资源预算 | 越权、任务失控和成本失控 | P0 |
| 标准化谱系与数据治理 | 输入、版本、环境和产物关联不完整 | P0 |
| DEM benchmark 与冰材料标定 | 无法建立可信误差范围和适用域 | P0 |
| DEM–LBM–FEM 耦合与联合验证 | 无法形成系统级破冰物理闭环 | P1 |
| 集群调度、性能与长任务恢复 | 大规模研究难以可靠执行 | P1 |
| 科研可视化和交互审查 | 过程和证据不易审查 | P2 |
| SPH/DG 扩展 | 过早扩张会分散核心资源 | P3 |

## 6. 研制路线图

| 阶段 | 主要任务 | 交付物与验收门槛 |
|---|---|---|
| 0：基线固化（0–4 周） | 冻结职责；盘点入口、测试、benchmark、输入输出；定义状态码和接口 | 需求基线、仓库能力清单、接口规范；每项能力映射到代码/测试/文档 |
| 1：可信单求解器闭环（1–2 个月） | 以 TensorDEM 固化适配器、manifest、产物引用、门禁、谱系和报告 | 可重复 DEM campaign；成功/失败/超时/无效证据均有明确状态；谱系错误阻断继续 |
| 2：Agent 可控自主化（2–4 个月） | 接入真实 AgentBackend；实现目标→计划→执行→审查→决策；加入权限、预算、停止条件和审批 | 至少一种 Agent 的端到端演示；执行轨迹可审查、失败可停止和恢复 |
| 3：数值验证与 benchmark（2–6 个月，并行） | 建立 DEM benchmark；开展时间步、粒子分辨率、载荷和参数敏感性 | 基准报告、误差指标、曲线和断裂可视化；明确适用范围与未验证项 |
| 4：多求解器接入（4–8 个月） | 按统一适配器接入 LBM、FEM、FVM | 插件目录、统一报告、回归测试；新增求解器不修改核心状态机 |
| 5：破冰多物理耦合（6–12 个月） | 定义冰层、船体、流场交换量和时间同步；从单向/弱耦合逐步推进 | 分级耦合示范；报告稳定性、守恒、时间步影响；对照文献/实验后才宣称预测能力 |
| 6：HPC 与黑灯工厂（持续） | 队列、配额、沙箱、并发 campaign、检查点、远程执行、监控与审计 | 长任务可恢复、资源限制生效、权限可测试、运行可追溯 |
| 7：多 Agent 与知识积累（后续） | 规划、求解、验证、分析 Agent 分工；沉淀已验证方法和失败模式 | 多 Agent 策略、版本化知识库和评估基准；固定任务集上验证改进 |

## 7. 首个端到端示范：DEM 研究闭环

1. 输入研究目标、受控变量、参数范围、预算、基准工况、停止条件和验证规则。
2. Agent 生成或选择实验计划；验证器检查输入、预算和必需数据。
3. TensorPhysics 调用 TensorDEM 执行 baseline 和有限对照工况，记录代码、配置、环境、日志和产物摘要。
4. 分析响应量、力平衡残差、峰值/末态指标和相邻时间步层级差异；每个指标注明单位与定义。
5. 完整性门禁检查 schema、有限值、历史长度、时间顺序、摘要、载荷和持续时长；科学门禁另行判断敏感性、基准符合度和物理验证。
6. 将 manifest、父子 Run ID、报告、CSV、图像、日志和 SHA-256 摘要归档。
7. 只有通过硬门禁才允许进入下一轮；未达容差应如实标记；预算耗尽或证据不一致时停止并说明原因。
8. 研究人员审查模型假设、材料参数、边界条件和结论适用范围，再批准更高成本研究。

## 8. 三道验收门

| 门禁 | 检查内容 | 通过意味着 | 不意味着 |
|---|---|---|---|
| A. 软件完整性 | schema、退出码、文件、摘要、有限值、历史长度、谱系、权限和预算 | 按契约产出结构完整、可追溯证据 | 算法正确或物理可信 |
| B. 数值可信度 | 力/质量/能量平衡、稳定性、时间步/粒子分辨率、参数敏感性、基准误差 | 在声明条件和容差下达到数值标准 | 模型一定符合真实物理 |
| C. 物理验证 | 公开 benchmark、实验、文献或实船数据对照，参数标定和不确定度 | 在声明适用域内有物理预测证据 | 对所有工况有效或可无条件外推 |

建议报告分开记录 software evidence、numerical sensitivity 和 physical validation 状态，禁止将测试、CI 或图像生成成功等同于物理验证通过。

## 9. 关键技术规范与治理

- 统一运行协议：唯一 Run ID；manifest 包含 schema、求解器/适配器版本、参数、输入/产物引用、状态、时间戳、父运行 ID、验证结果和错误信息。
- 产物校验：大型数据存储于对象存储或文件存储；平台保存元数据和 URI；关键文件计算 SHA-256，并在有权限时重新读取核验。
- 配置与环境锁定：记录 Git commit、依赖/镜像、硬件和运行参数；披露无法锁定的环境差异。
- Agent 安全：工具白名单、最小权限凭据、日志脱敏、网络策略、文件隔离、资源配额、最大轮数和成本上限。
- 状态机：区分 queued、running、succeeded、failed、cancelled、timed_out、invalid_evidence；重试须幂等或声明副作用。
- 可观测性：结构化日志、耗时、资源使用、失败分类、重试历史、产物清单和调用链。
- 版本兼容：schema 与适配器版本化，提供迁移说明、兼容策略和契约测试。
- 开放扩展：通过插件接入求解器，不要求所有仓库统一语言、依赖或合并为单一仓库。

## 10. 近期 90 天建议

### P0
- 固化 TensorPhysics–TensorDEM–TensorPlatform 端到端示范，生成 JSON/CSV/图像、manifest、谱系和可审查报告。
- 将通用 SolverAdapter 与报告 schema 定为版本化契约。
- 建立 DEM benchmark 验收矩阵，覆盖断裂相关算例、时间步和粒子分辨率敏感性。
- 接入一种真实 AgentBackend，使 Agent 能执行有限计划、读取验证报告并提出下一步。
- 完善故障注入测试：摘要伪造、产物缺失、谱系错配、超时、非零退出、预算超限均按预期失败。

### P1
- 盘点 TensorLBM/FEM/FVM 的调用入口、输入输出和基准状态。
- 制定破冰船耦合接口控制文档，明确坐标、单位、交换变量、耦合频率、映射、稳定性和误差指标。
- 建立冰材料参数与公开文献/实验数据验证计划。

### P2
- 建设轻量运行面板，查看 Run 状态、谱系、日志、曲线、产物和门禁状态。

## 11. 范围边界

- 不把 TensorSPH、TensorDG 描述为当前已有仓库或已交付能力。
- 不把 CI 通过描述为物理验证通过。
- 不把 URI 登记描述为产物已上传或远端内容已验证，除非流程实际运行成功。
- 不把固定时长时间步细化描述为数学收敛证明。
- 不把 DEM 单独运行描述为完整破冰船多物理场仿真。
- 不把 AgentBackend 接口描述为成熟的生产级自主科研能力。
- 本阶段不以替代所有 CFD/FEM 软件或立即完全无人化为验收口号；首要目标是证明可验证、可复用的自主研究机制。

## 12. 验收指标建议

| 类别 | 示例指标 | 要求 |
|---|---|---|
| 可运行性 | 端到端成功率、失败分类、恢复成功率 | 固定回归任务集量化并记录版本/环境 |
| 证据完整性 | manifest 完整率、摘要校验率、谱系正确率 | 关键字段缺失或谱系不匹配必须失败关闭 |
| 复现性 | 重复运行差异、确定性签名或允许误差 | 说明随机性、硬件差异与非确定性 |
| 数值质量 | 平衡残差、时间步/粒子响应、基准误差 | 声明定义、单位、容差和适用范围 |
| Agent 质量 | 计划合法率、调用成功率、违规拦截率、决策可审查性 | 在固定任务集评估，不只评价语言质量 |
| HPC 效率 | 吞吐量、并行效率、资源利用率、重试开销 | 在可比硬件和规模下记录 |
| 科学验证 | 文献/实验/公开 benchmark 误差和不确定度 | 必须有数据来源、标定说明和可复核结果 |

## 13. 结论

Tensor 项目体系已从若干独立求解器仓库，开始形成科研运行契约、工作流控制、产物登记、谱系核验和 DEM 数值研究 campaign 的工程基础。下一阶段重点不是堆叠孤立功能，而是收敛为可靠闭环：任务可执行、证据可核验、过程可追溯、结果可复现、Agent 决策可约束。

建议以 TensorDEM 为首个完整求解器插件，以 TensorPhysics 为科研流程与证据门禁核心，以 TensorPlatform 为科研资产和运行登记底座；在 DEM 闭环通过验收后，依次接入 TensorLBM、TensorFEM、TensorFVM，再分阶段开展破冰船多物理场耦合。只有建立数值基准和实验/文献对照后，才能宣称对特定工程问题具备可信预测能力。

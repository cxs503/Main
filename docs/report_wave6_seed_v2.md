## 2 怎么做（方法 / 流程 / 工具链）

### 2.1 聚合去重流程

1. **装配输入**：读三位提案者任务（1026, 1027, 1028）的提案池工件 `prop-1026/1027/1028.json`，
   共 18 条提案（每源各 6/6/6 条），保留 `id/repo/physics_domain/why_frontier`。
2. **语义重叠判定**：按"物理对象 × 数值方法"二元组比对；同一物理对象且方法栈可
   共享同一场交换接口者判为重叠，合并为单一节点并**吸收两家可取细节**（例如
   水动力干涉系数矩阵 + 通道再冻结热力学 → 同一 DEM 多体节点内双交付物）。
3. **互补保留**：重叠判据不成立者按提案原样成节点，不改物理目标。
4. **元数据契约**：每节点 `metadata` 必含 `ext_id`（全库唯一新前缀 `W6-N..`）/
   `repo`（白名单）/`goal`（≥80 字完整任务书：物理目标 + 机器可算判据 +
   纪律 "全新前沿 / worktree 内提交自己分支 / 论文级报告 / honest FAIL 不可覆盖"）/
   `acceptance_criteria`（机器可算数组）/`proposal_src`（**来源提案者任务 id**，
   即任务书要求的 `[来源提案者任务id]` 形态）。
5. **播种**：只 INSERT/UPDATE 数据，不改表结构（禁 ALTER）；写
   `campaign_plans` 一行（`status='draft'`，metadata 带 `parent_plan` 与
   `seed_report`）+ `campaign_milestones` 3 行 + `campaign_nodes` 10 行。
6. **机器门自检 → 审计复检**：先按任务书 7 项门自检，再以独立脚本
   （`artifacts/audit_wave6_seed.py`）从 DB 复算 10 项门 + 溯源/去重三类审计。

### 2.2 审计工具链（本返工新增，可复跑）

| 环节 | 实现 | 判据 |

## 6 误差判定（新增独立节，逐项显式回答「是否<3%」）

### 6.1 关键量的性质声明

本报告为**战役规划（seed）文档**：关键量全部是**布尔校验项与整数计数**
（机器门 10 项、溯源归因数、记账平衡），**不存在连续数值量**（无阻力、无功率、
无运动响应、无应力），因此**没有可与实验/文献/解析解逐项比对的数值基准**。
精度纪律中「相对误差 >15% 不可接受」「关键量 vs 基准误差 <3%」两条判据，
其定义域为物理连续量；对布尔/计数项，相对误差**不成立（分母无物理意义）**。
本节因此改为报告**可机读的等价判据**：原报告 832 自述值 vs 本审计复算值的
**一致性**（0 = 完全一致）。

## 7 注意点（踩过的坑 / 局限 / 后续建议）

**坑（本单踩到的）**

1. `proposal_src` 存的是**任务 id 而非提案 id**（任务书原文即如此要求），一度
   按提案 id 解析导致溯源审计全面误判 0/18；修正为"任务级合规 + 提案级重建"
   双轨后才可核（见 §5.1）。
2. 节点标题被改写为通用物理描述后，与原提案标题的字符二元组相似度骤降到
   0.06–0.27 区间；阈值设 0.10 是**证据与误判的折中**，不能当作"归因正确"的
   强证据——故对低于阈值的两条自述归因判 WITHHELD 而非强行匹配。
3. 播种后 plan 状态会由战役控制器从 `draft` 推进为 `active`；报告若照抄播种
   时点状态，审计时即出现"自述过期"（F3）。
4. 审计中 `cut -c` 截断中文 JSON 会破坏多字节编码；取数须整列 JSON 落文件再解析。

**局限**

- 提案级溯源重建依赖字符相似度，对同源同域提案（如同一提案者的 6 条都在冰区）
  区分力有限；阈值附近的判定只能算旁证。
- 审计对象为 DB + 提案池工件，未审计三位提案者内部推理质量（其 `why_frontier`
  的新颖性主张未独立核实）。
- 未归因的 7 条提案（`prop-1026-01`, `prop-1026-03`, `prop-1026-04`, `P5W1-06`, `prop-1028-01`, `prop-1028-02`, `prop-1028-03`）在战役层被**丢弃**，原始提案未记录丢弃理由，属流程
  缺口（本报告只能如实标注其存在）。

**后续建议**

- **R1**：后续 Wave 播种时在节点 `metadata` 增字段 `proposal_ids: [...]`
  （提案 id，而非仅任务 id），并在 plan `metadata` 记录
  `dropped_proposals: [{id, reason}]`，把提案级溯源从"重建"升级为"机读断言"。
- **R2**：跨仓合并节点（如 W6-N02）显式记录 `repo_host_source`（哪条提案提供
  宿主仓库），消除 §5.2 的可见性缺口。
- **R3**：把 `artifacts/audit_wave6_seed.py` 的 10 项门复算接入派发器预检，
  让"自检 vs 审计"双轨常态化。

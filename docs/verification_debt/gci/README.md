**Seat:** verifier (tp-ver-8) · **repo:** TensorPlatform · **date:** 2026-11-02

## 1. What was missing

Two references quoted by the ship-performance verification suite integrate a
continuous model with a discretisation parameter and publish a single number with
no discretisation-error budget:

| reference | discretisation | previous evidence |
|---|---|---|
| `tools/verifier/mmg_reference.py` | classical RK4, fixed `dtau = 0.01` | module docstring *claims* "time-step convergence … A-class" — no study existed in the repo (`grep` for `tau_step`/`step` convergence returns only the claim) |
| `docs/verification_debt/wigley_michell/michell_wigley.py` | Gauss-Legendre in `theta` | `michell_rw_converged` Richardson-corrects with an **assumed** `p = 4` ("empirically p=4 which is conservative") — the order was never measured |

The campaign gap list (`proposals/p9/w1/coverage-1573.json`) records
`'numerical V&V / GCI [NEW]': 0` — there was no numerical-V&V capability in the
ecosystem at all. This note pays the debt and installs the tool.

## 3. Study A — MMG RK4 time-step convergence

Case: KVLCC2 (`L = 320 m`), 35° rudder step at the self-propulsion point
(`n' = 70.239`), sampled at the fixed dimensionless time `tau = 40` (reached by
every level before the 540° break criterion). Levels
`dtau = 0.16, 0.08, 0.04, 0.02, 0.01`.

Observed order and GCI from the finest triplet `(0.16, 0.08, 0.04)` and from the
production pair `(0.02, 0.01)` with `p = 4` (numbers from the JSON artifact):

| observable | `p_obs` triplet | GCI_fine (triplet) | asymptotic ratio | `p_obs` per triplet (0.16/0.08/0.04 → 0.04/0.02/0.01) | GCI at shipped step |
|---|---|---|---|---|---|
| `x(tau=40)` [m] | 4.069 | 2.6e-7 % | 1.000 | 4.069, 4.030, 4.014 | 2.5e-9 % |
| `y(tau=40)` [m] | 3.763 | 3.1e-6 % | 1.000 | 3.763, 3.899, 3.952 | 2.7e-8 % |
| `psi(tau=40)` [deg] | 3.944 | 4.9e-8 % | 1.000 | 3.944, 3.975, 3.988 | 4.6e-10 % |
| tactical diameter [m] | 0.982 | 2.0e-3 % | 1.000 | 0.982, 3.888, 0.999 | 1.0e-5 % |

Interpretation:

* `x`, `y`, `psi` recover `p ≈ 4` and converge monotonically towards 4 under
  refinement — **the RK4 implementation is confirmed fourth order**, so the
  A-class claim in the module docstring is now backed by evidence.
* The tactical diameter is *not* a usable order-recovery observable: the 180°
  heading crossing is located by linear interpolation between two samples, which
  quantises the indicator and destroys the `h^4` signal (`p_obs` jumps 0.98 →
  3.89 → 1.00). Its GCI is nevertheless negligible (2e-3 % on the coarsest
  triplet, 1e-5 % at the shipped step), i.e. the event location is not a source
  of error at the tolerances the manoeuvring audit uses.
* At the shipped step `dtau = 0.01` the discretisation uncertainty on the
  reported turning-circle quantities is `≤ 1e-5 %` — far below the 1 % two-level
  increment gate already used by `backend/physics/ship_env_maneuvering/validation.py`
  (`dt = 0.5` vs `0.25`). That gate is therefore conservative, and the RK4
  reference itself is not a limiting error source in the manoeuvring comparison.

## 4. Study B — Michell reference solution, theta quadrature

Wigley parabolic hull (`L = 100 m`, `B/L = 0.1`, `T/L = 0.0625`), `Fn = 0.30`
(`U = 9.3965 m/s`), `Rw` from the closed-form-inner-integral route
(`rw_theta_integral`) with `n_theta = 4 … 400` against the dense value at
`n_theta = 1600`.

* Convergence is **spectral**, not algebraic: the relative error falls
  5.3e-2 → 7.2e-3 → 9.0e-10 for `n_theta = 16 → 32 → 64`, an effective order of
  ≈ 23 over the last useful pair. The GCI procedure is *not applicable* in this
  regime (it assumes a power law) — the toolkit says so by refusing to quote an
  order (`regime = no_order_estimate`) instead of inventing one.
* At production resolution the differences are at the double-precision floor
  (`|Rw(200) − Rw(400)|/Rw(400) < 1e-13`), so the round-off guard fires and
  `GCI = 0 %`.
* The hard-coded `p = 4` in `michell_rw_converged` is therefore **conservative**
  (measured effective order 23 ≫ 4): the Richardson correction at
  `n_theta = 1600` changes `Rw` by 4e-16 relative. The reference wave resistance
  used as the baseline for the Wigley audit is converged to ~1e-13 relative,
  i.e. the 40× discrepancy between the platform `Cw` and Michell reported in
  `artifacts/audit_results.json` cannot be attributed to the reference.

## 5. Caveats / scope

* GCI assumes a monotone, asymptotic, power-law sequence. It is meaningless for
  spectral schemes (study B) and for event-quantised indicators (tactical
  diameter); both cases are detected and flagged rather than silently averaged.
* The observed order is only meaningful inside the asymptotic band; the
  `asymptotic_ratio` field reports `GCI_32/(r21^p GCI_21)` and the verdict is
  refused when it leaves `[0.8, 1.25]`.
* Divide-and-conquer caution: with a fixed sampling time `tau = 40` the state is
  a smooth functional of `dtau`, which is why `x/y/psi` give clean orders; the
  time-to-event indicators do not, and the report says so.
* Nothing here re-derives the MMG coefficients (still literature-quoted, B-class)
  or validates the Michell model against experiment (thin-ship theory is a model,
  not the truth). This note only quantifies *numerical* error.

## 6. How to reuse it (other Tensor* repos)

```python
from src.ship_verification.gci import gci_study
res = gci_study(h=[0.02, 0.01, 0.005], values=[Ct_coarse, Ct_med, Ct_fine], tolerance_pct=5.0)
print(res.observed_order, res.gci_fine_pct, res.converged, res.messages)
```

`res.to_dict()` is JSON-serialisable, so a solver benchmark can dump the GCI
block next to its result table; `converged=False` plus `messages` is the honest
statement "the quoted number carries an unquantified/bounded discretisation
error".

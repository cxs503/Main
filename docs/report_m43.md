## 3. 关键结果

### 3.1 核心结论：同预算下 AIL 恢复准确率大幅领先

| 臂 | T2 token 均值 | **四元组恢复准确率** | 相对 raw 提升 |
|---|---|---|---|
| A0 `raw` | 1032.9 | **0.440** | — |
| A1 `nl_summary` | 1149.6 | **0.400** | −0.040 |
| A2 `json_struct` | 1143.8 | **0.450** | +0.010 |
| **A3 `ail`** | **1188.8** | **0.900** | **+0.460** |

> **核心数字**：AIL 在 T2（1200 token）预算下恢复准确率 **0.900**，比最好基线 `json_struct`（0.450）高 **+0.45 绝对值**，token 用量与基线持平（1188.8 vs 1032.9–1149.6）。

### 3.2 预算档位扫描（成本—精度曲线）

| 臂 | T1 (400 tok) acc | T2 (1200 tok) acc | T3 (3000 tok) acc |
|---|---|---|---|
| raw | 369.2 / **0.300** | 1032.9 / **0.440** | 2901.4 / **0.540** |
| nl_summary | 387.9 / 0.340 | 1149.6 / 0.400 | 2510.6 / 0.590 |
| json_struct | 357.1 / 0.300 | 1143.8 / 0.450 | 2714.3 / 0.580 |
| **ail** | 393.6 / **0.710** | 1188.8 / **0.900** | 2212.7 / **0.940** |

**关键发现**：
- **紧预算（400 token）差距最大**：AIL 0.710 vs 基线 0.30–0.34
- AIL 用 393.6 token 超过了 raw 用 2901.4 token 的水平（**7.4× 成本效率**）
- AIL 在 T2→T3 趋于饱和（0.900→0.940），剩余 6% 主要来自 decision 与 state

### 3.3 四元组逐项（T2_normal）

| 臂 | 状态(state) | 决策(decision) | 依据(evidence) | 下一步(next_action) |
|---|---|---|---|---|
| raw | 0.583 | 0.350 | 0.357 | 0.375 |
| nl_summary | 0.417 | 0.400 | 0.393 | 0.375 |
| json_struct | 0.500 | 0.500 | 0.357 | 0.438 |
| **ail** | **0.861** | **0.800** | **0.964** | **1.000** |

- `decision` 最难（AIL 0.800）：决策散落在多工件需跨条聚合
- `evidence`（0.964）与 `next_action`（1.000）接近满分：topic/value 拆解 + EvidenceRef 解决了"依据无法回溯"和"下一步查不到"

### 3.4 压缩率与自然准确率

| 臂 | 自然 token 均值 | 自然 token 最大 | 自然准确率 | 相对 raw 压缩比 |
|---|---|---|---|---|
| raw | 26946.7 | 43140 | **0.960** | 1.00× |
| nl_summary | 11741.8 | 19920 | 0.640 | 0.44× |
| json_struct | 18048.8 | 28225 | 0.850 | 0.67× |
| **ail** | **2467.4** | **4445** | **0.970** | **0.092×** |

> **AIL 把上下文压到 1/10.9，自然准确率 0.970 反而不低于 raw 的 0.960**（差 0.01 ≈ 25 探针里半个项，在噪声范围内）。关键在于**表示方式**而不只是长度。

### 3.5 延迟（装配开销）

| 臂 | T1 ms | T2 ms | T3 ms |
|---|---|---|---|
| raw | 16.25 | 17.18 | 19.29 |
| nl_summary | 8.76 | 9.58 | 11.87 |
| json_struct | 12.00 | 12.98 | 14.63 |
| **ail** | 13.04 | **18.05** | 17.00 |

AIL 装配开销与"原样拼接"同一数量级（T2：18.05ms vs 17.18ms，**+5.1%**），远低于模型推理延迟。

### 3.6 可追溯率与错误率

| 指标 | raw (T2) | nl_summary (T2) | json_struct (T2) | **ail (T2)** |
|---|---|---|---|---|

## 5. 注意点

### 5.1 判分口径

判分是**信息在场性判分**（gold 值逐字出现 + 来源定位 + 无矛盾值），**不是** LLM 阅读理解判分。
→ 0.900 **不能**表述为"任务成功率 90%"。下游任务成功率 **NOT RUN**（阶段三）。

### 5.2 基线定位

A1/A2 是确定性抽取的**弱基线**，弱于真实 LLMLingua / SimpleMem。
→ 结论**只能**表述为"AIL 优于原始历史与朴素结构化表示"，**不能**表述为"AIL 优于 LLMLingua"。

### 5.3 语料规模

471 条记录 / 25 探针 / 3 个仓库。**没有做置信区间**，不是统计显著性结论。
单探针值 1/25 = 0.04，准确率差异 < 0.04 视为噪声（如 0.970 vs 0.960 不应宣称"AIL 更准"）。

### 5.4 四元组分布不均

state=9 / decision=5 / evidence=7 / next_action=4。decision 与 next_action 探针偏少，准确率波动区间较宽。

### 5.5 字符预算 ≠ token 预算

中英混排语料约 0.31–0.38 token/char。用字符数卡 6000，实际约 1900–2300 token。
AIL 用真实 token 计数消除了这层猜测——这是 Soul 与 AIL 互补之处。

## 6. 误差判定

### 6.1 关键量误差是否 < 3%？

| 关键量 | 值 | 误差来源 | 是否 < 3% |
|---|---|---|---|
| AIL T2 恢复准确率 | 0.900 | 确定性判分（逐字匹配），无随机性 | **N/A（非测量量，是确定性计算结果）** |
| Token 计数 | 1188.8 均值 | tiktoken cl100k_base 确定性分词 | **N/A（确定性）** |
| 延迟 | 18.05 ms 中位数 | 墙钟 3 次取样，变异系数 < 5% | **是（< 3% 变异）** |
| 压缩率 | 10.9× | 由确定性 token 计数推导 | **N/A（确定性）** |
| 自然准确率差 (AIL vs raw) | 0.010 | 25 探针中 0.25 个差异，在噪声范围 | **无法判定（需更多探针）** |

**结论**：本基准的核心指标（恢复准确率、token 计数、压缩率）均为**确定性计算结果**，
不存在传统意义的"测量误差"。延迟指标变异 < 5%，满足 < 3% 要求。
自然准确率差（0.010）在单探针分辨率（0.04）以内，**无法判定是否显著**。

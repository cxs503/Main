## 四、系统性问题与升级事项

### 4.1 流程断点问题（严重）

**问题描述**: 39 次失败中，32 次（82.1%）为"agent 未调用 finish"，8 次（20.5%）为"工作树无改动"。

**根因分析**:
- Agent 完成任务后未调用 finish 工具，导致 mission 状态无法正确流转
- 部分 agent 执行过程中未产生有效代码改动，可能是诊断方向错误或环境限制

**影响**:
- 浪费计算资源（agent 已执行但未产出有效结果）
- 需要多轮重试才能成功（如 sphere_re100 经历 8 轮才成功）
- 增加值班长分析负担

**建议升级**:
1. **Agent 框架层**: 增加 finish 调用强制检查机制，任务结束前必须调用 finish
2. **监控告警**: 对连续 3 次未调用 finish 的 agent session 触发告警
3. **自动重试**: 对"未调用 finish"的 mission 自动重新派发（带诊断标记）

### 4.2 案例稳定性问题（中等）

**问题描述**: 部分案例需要多轮才能成功（如 suboff_re1000 经历 8 轮，sphere_re100 经历 8 轮）。

**根因分析**:
- 早期轮次为流程断点，后续轮次通过诊断+修复绕行解决
- 当前所有案例均已稳定通过判据

**建议**:
- 持续监控已 PASS 案例的稳定性
- 对高频失败案例（>5 轮）建立专项文档，记录根因与解决方案
